# WEB-006 · Distribución estática y autónoma

Base inmutable: WEB-005, commit `1fa920c92f8f02faa78d65cfde669810bd95bdc6`. Nueva rama `feat/web-006`; ningún cambio en PR #11 o ramas anteriores. Solo herramientas/documentación en Git público; corpus y artefactos completos fuera del repositorio. No se despliega ni se toca Cloudflare, DNS, Workers o producción.

## Salidas

- `DAYZ-SURVIVAL_HTML_AUTONOMO.html`: archivo único, CSS/índice/páginas/lector embebidos, navegación hash y búsqueda sin servidor ni red. Reutiliza el puente offline de WEB-005; solo versiona su exportador de comentarios.
- `DAYZ-SURVIVAL_CLOUDFLARE_READY.zip`: `index.html` en raíz, sin carpeta envolvente; 308 páginas de artículo, ocho familias, dos atlas separados, búsqueda, proyecto/revisión/404 y cinco documentos de referencia necesarios. Sin runtime, instaladores, fuentes de desarrollo, Functions o `_worker.js`.
- Informe, SHA-256 y guía para Direct Upload mediante la interfaz web, separados del contenido desplegable.

ARCHIVE-86 y los textos permanecen sin cambios. Se exporta el build Astro ya validado, no se reconstruye la aplicación. La etiqueta de distribución y la exportación de comentarios pasan a WEB-006. Se elimina el enlace de descarga de Markdown y se aclara esa eliminación en la página de procedencia; no se cambia el cuerpo de los manuscritos.

Los originales y sus ZIP históricos siguen fuera del paquete de distribución y fuera de Git. Los cinco documentos auxiliares que el corpus cita se convierten a páginas de referencia de texto completo, escapado, sin ejecución; sus vínculos se actualizan sin alterar las palabras del artículo. Son tres ficheros de matrices, un protocolo y un registro de afirmaciones, todos citados; no alteran el recuento histórico de cuatro matrices derivadas ni añaden plazas. No se incluyen archivos Markdown/JSON auxiliares sin procesar, manifiesto de prompts de ilustración, fuentes originales, backups, datos de evaluación, rutas privadas ni registros de construcción.

El manifiesto mínimo de integridad contiene 308 IDs, hashes del origen y texto presentado, estados editoriales originales y límites técnicos. No expone punteros privados. Las 208 propuestas y demás estados históricos se conservan; la autorización de revisión privada no es publicación ni certificación 1.30. La evidencia técnica sigue pendiente y el filtro “verificado en cliente” devuelve cero.

No se generan `_headers` o `_redirects`: las rutas y MIME funcionan con el comportamiento estándar comprobado de Pages. Hay un `404.html` real, evitando fallback SPA para rutas inexistentes. Se conservan `noindex,nofollow` y `robots.txt` con `Disallow: /`; no son control de acceso. Un `pages.dev` público expondría el corpus aunque no se indexase. La carga se deja al propietario tras autorización expresa.

## Repetición técnica (solo Codex/mantenedor)

```sh
python3 tools/web-006/export-static.py --source /ruta/build-web005 \
  --corpus /ruta/entrega-integral.zip --output /ruta/nueva-salida
python3 tools/web-006/build-standalone.py /ruta/nueva-salida /ruta/nuevo-autonomo.html
python3 tools/web-006/verify-export.py /ruta/nueva-salida /ruta/nuevo-autonomo.html /ruta/entrega-integral.zip
```

El SHA del ZIP integral se comprueba contra el checksum independiente de Drive. Los destinos existentes se rechazan para preservar entregas anteriores. Se comprueba cada hash Markdown contra el integral y cada texto presentado contra la referencia de WEB-005, tanto en páginas como en el HTML autónomo. Se verifican IDs, todos los enlaces/recursos y fragmentos, duplicados DOM, tipos de archivo, tamaños, patrones de secretos/correos/teléfonos/DNI/IBAN/rutas privadas. Un escaneo de patrones no prueba ausencia universal de toda información personal; no se inventa esa garantía.

El ZIP se genera con nombres relativos desde su raíz, se comprueba CRC, se extrae a carpeta nueva y se compara byte a byte. Se prueba únicamente esa extracción usando `wrangler@4.156.1 pages dev`, IP loopback, métricas deshabilitadas y sin login, bindings externos o llamadas de despliegue. Las variables `CF_PAGES_URL` que imprime el emulador son sintéticas, no URLs remotas existentes.

`audit-distribution.mjs` comprueba Pages local y el HTML bajo `file://` real con Chromium de Playwright: 320/768/1440 CSS px, teclado, menú, búsqueda universal/múltiples resultados, filtros, vacío, paginación, lector/A−/A+, referencias, atlas, JSON/TXT, no-JS en páginas y axe. La versión autónoma se carga offline sin solicitudes HTTP. Windows/NVDA/Narrador y dispositivos físicos no se afirman ejecutados.

La documentación oficial Direct Upload se consultó en el repositorio público de Cloudflare: [direct-upload.mdx](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/docs/pages/get-started/direct-upload.mdx). Documenta ZIP o carpeta mediante drag and drop, 1.000 archivos y 25 MiB por archivo. El paquete tiene 332 archivos y su mayor recurso ronda 1 MiB. El propietario no necesita npm, Python, Node o compilación. No se ha comprobado su sesión del panel ni sus permisos reales, ni se supone que se hayan configurado accesos o cuentas.

## Rollback y revisión

Sin despliegue, no hay cambio remoto que deshacer: cerrar el emulador y conservar WEB-005/WEB-004. Descartar esta rama no afecta sus artefactos. Una carga futura debe usar un proyecto Pages independiente; no sustituir el dominio existente. Un rollback posterior sería una acción autorizada del propietario desde el historial de despliegues, no una acción realizada aquí.

La aprobación final de interfaz y publicación sigue pendiente. Los checks automáticos no certifican mecánicas, derechos cartográficos ni lectores de pantalla. El informe privado de entrega recoge resultados, evidencias, hashes y límites reales; no se sube el corpus ni capturas reales a Actions.
