# ADR-001: Static reader and an explicit editorial boundary

Date: 2026-10-23. Status: accepted for the local v0.1 implementation.

The first delivery must prove reading, navigation, search and cross-references without bringing the private Fuente Maestra into a public code repository. Astro and TypeScript produce static documents. Small browser scripts handle the menu and local search; the reader does not need an application server, account system, database or Cloudflare binding.

The v0.1 corpus is one synthetic article and its quick card. Demo labels remain visible on every route. Atlas pages are separate placeholders, not inferred maps or gameplay guides. No CHERNO++ source or editorial content is reused.

Editorial approval and technical evidence are different fields. A future importer reads a separately authorized export and an exact allowlist, verifies identifiers, content hashes and provenance, and rejects material outside that contract. The original master remains outside Git and is never modified. Demo fixtures cannot become approved content through a filename, an environment variable, or a successful application build.

CHR, LIV and AUD-130 are distinct review lanes. D26 remains blocked. C29, E30, CE26 and D30DOC remain distinct evidence classifications. Neither an approved article nor an isolated build reference establishes DayZ 1.30 Stable certification.

The static build is a local review artifact, not publication authorization. CI runs validation, compilation, unit tests and Chromium accessibility/integration checks only. A future hosting decision needs separate approval and configuration; no production domain or deployment workflow is included.

Tradeoffs: search downloads a small index to the browser, which is suitable for the initial 84-article target but must be measured when approved content is available. Browser-only interactions require JavaScript; static article text and ordinary navigation remain usable without it. Automated accessibility checks detect a subset of issues and do not replace keyboard, assistive-technology and editorial review.
